FIX 1: C-1 (CRITICAL) VisualProgress cash dupe
Module: ServerScriptService/Server/BuildService
Function: local function payParts(player, record)
=====================================================================================================
WHAT IS WRONG
payParts computes placed = min(server placed, record.visual), where record.visual is the count the
client reports through the VisualProgress remote. When that is 0 it resets record.paid = 0.
A hacked client fires VisualProgress(0) then VisualProgress(N) (N = real count). The first call
resets paid, the second pays the whole build's per part cash again. Main allows 8 reports per second,
so this repays the build 4 times a second. Negative or -math.huge counts also clamp to 0.

FIND (inside payParts):
	local paid = record.paid or 0
	if placed == 0 then
		record.paid = 0
	elseif due > paid then

REPLACE WITH:
	local paid = record.paid or 0
	if record.state:getPlaced() == 0 then -- only the SERVER's count may reset what was paid (a client report of 0 must not)
		record.paid = 0
	elseif due > paid then

WHY THIS IS ENOUGH
A fake 0 now gives due = 0 and pays nothing, and paid stays where it was. A fake N afterwards gives the
same due as before, which is not greater than paid, so nothing is paid twice. Rebirth (resetRun) and a
new build still reset paid because the server count really is 0 then.
Do NOT make record.visual "monotonic"; that would break the visual gate at the start of each build.

FIX 6: P-1 (MEDIUM) Gift ping pong burns the DataStore write budget
Module: PetSocial  (local function persist)
=====================================================================================================
WHAT IS WRONG
Every accepted gift calls saveNow for both profiles. Two players passing a pet back and forth burn
the UpdateAsync budget; ProfileStore keeps only 5 in reserve, so other players' autosaves get
deferred.

STEP 6.1  Module level:

local persistedAt: { [any]: number } = {}

STEP 6.2  Replace the body of local function persist(a, b) (keep the signature):
local function persist(a: any, b: any)
	local save = deps.save
	if save == nil then
		return
	end
	local t = os.clock()
	if t - (persistedAt[a] or -math.huge) < PERSIST_GAP or t - (persistedAt[b] or -math.huge) < PERSIST_GAP then
		return -- one of them was saved moments ago: skip BOTH (a crash then rolls both back together); the 60 s autosave covers it
	end
	persistedAt[a], persistedAt[b] = t, t
	for _, p in { a, b } do
		task.spawn(function()
			pcall(save.saveNow, save, p)
		end)
	end
end

STEP 6.3  In PetSocial's removePlayer / PlayerRemoving handler add:  persistedAt[player] = nil
